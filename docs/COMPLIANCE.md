# 数据与应用合规说明

## 使用边界

Cellcloak 是一个**本地聚合表发布前审查工具**，不是匿名化、去标识化或差分隐私系统。使用者必须确保：

- 只处理本人拥有，或已获得明确授权的本地聚合数据。
- 输入数据已经按组织政策完成必要的数据治理审查。
- 输出发布判断由具备统计披露控制知识的人员复核，而非单靠本工具自动放行。
- 不将工具输出当作法律意见、合规认证或“无再识别风险”的证明。

仓库中的示例数据全部为合成数据。`R01`、`R02` 等地区编码与年龄分组均为虚构值；不含真实个人信息、真实公司名、真实域名、密钥、令牌或目标地址。

## 完全离线

运行期不发起网络请求：

- 不调用外部 API、CDN、遥测、消息队列、远程数据库或云存储。
- Flask 页面没有远程资源引用；CSS 本地打包，审计 HTML 自包含。
- 没有用于抓取 URL 或上传任意路径的 Web 入口。
- 依赖仅限 Python 标准库、Flask、PyYAML 与测试用 pytest。安装依赖需要由使用者在受控环境预先完成。

## 仅回环监听

`serve` 只允许 `127.0.0.1`、`localhost` 或 `::1`；显式拒绝 `0.0.0.0` 及非回环主机。页面没有鉴权系统，因为其定位是单机本地界面，不应暴露到局域网或公网。若本机存在不可信多用户，请自行使用操作系统账户隔离、文件权限或本地防火墙。

Web 响应设置：

- `Content-Security-Policy`：禁止脚本、外部资源与 frame 嵌入；
- `X-Frame-Options: DENY`；
- `X-Content-Type-Options: nosniff`；
- `Referrer-Policy: no-referrer`。

错误页不展示服务端堆栈、数据库路径或临时目录。

## 原始小计数的处理

- `public/` 只包含遮蔽后的公开表，被抑制单元格为 `NA`，不包含原始小计数。
- `audit/report.json`、`.md`、`.html` 有意不展示被抑制单元格原始计数，只展示坐标、指纹、风险类别、聚合统计与核验证据。
- 原始计数仅写入本地 SQLite 台账的 `cells` 表，该表明确为内部数据，并附运行 ID、抑制类型、风险类别和指纹。
- 指纹由表 ID 与行列键计算，不包含计数值，避免用指纹旁路泄露小计数。
- 运行 ID、输入哈希、契约哈希、公开表哈希进入台账与报告，便于复核。

**内部审计目录与 SQLite 数据库不是公开发布物。** 不得把它们上传到公共仓库、对象存储、分析平台或工单附件。确有内部共享需要时，应按组织的数据分级与最小必要原则处理。

## 文件与保留

- 默认台账：`var/cellcloak.sqlite3`；可通过 `--db` 或环境变量 `CELLCLOAK_DB` 指向受控目录。
- 默认 Web 演示输出：`var/web-demo`；可通过 `CELLCLOAK_WEB_OUT` 调整。
- 运行产物位于调用者传入的 `--out` 目录。请使用专用目录并设置适当的操作系统权限。
- 工具不自动删除历史台账记录。保留期限、备份、加密、访问审计与销毁流程由使用方负责。
- 保留期结束后，用 `python -m cellcloak forget --run <id> --reason <code>` 删除该 run 的原始单元格记录（`cells` 等台账行）与内部报告文件（`audit/report.json/.md/.html`）；先用 `--dry-run` 审阅清单。公开表 `public/*.csv` 不含原始计数，是否保留由发布方决定。
- `forget` 只删除同时满足以下条件的文件：台账登记于该 run、被输出目录 `.cellcloak-output.json` 清单确认、路径解析后不越出该 run 的输出目录、非符号链接、未被其他保留 run 引用、磁盘 SHA-256 与登记值一致。不满足即保留并给出具体原因；共享输出目录中属于后来 run 的文件不会被误删。
- 清除后保留最小审计墓碑（`run_id`、删除时间、原因码、聚合删除结果），不含原始计数、坐标键与内部报告路径；`runs`/`verify` 会显示 `purged`/`purging` 状态而非当作从未存在。墓碑本身是审计证据，请按组织政策决定其保留期。
- 输出清单 `.cellcloak-output.json` 仅用于防止跨运行遗留公开表；不构成数据保留政策。

## 统计披露控制限制

本工具实现的是可解释的工程启发式：

- 互补抑制不保证最小基数，也不使用整数规划等外部求解器；
- 只处理二维计数表；
- 反推核验聚焦行/列边际的单未知数级联，不证明所有联合推断、表间关联或辅助信息攻击都不可行；
- 不实现差分隐私，不提供形式化隐私预算；
- `max_suppression_ratio` 是披露约束，不是隐私保证；
- 结构零与强制抑制规则由契约声明，工具会检查结构零的实际取值，但不会替使用者判断业务语义。

发布组织仍应结合抽样设计、权重、极值、时间序列差分、跨表地理层级、已知总体边际、公开登记信息等上下文复核。

## 安全使用建议

1. 在隔离的本地环境解压与运行；不要从不可信来源加载 YAML 或 CSV 之外的代码。
2. 使用 `yaml.safe_load` 的契约读取已内置；不要修改为 `full_load`。
3. 审阅 `public/` 中除遮蔽值外的边际，确认不存在业务上的额外泄露。
4. 将 `audit/` 与 SQLite 台账纳入内部数据资产管理，而非普通构建产物。
5. 若发现公开表含有不应出现的小计数，立即停止发布，保留台账证据并按组织流程处置。
6. 定期用 `forget` 清理到期运行的原始记录与内部报告，遵守最小必要与保留期限要求。

## 事件处理提示

如果怀疑公开产物误包含原始小计数：

- 停止分发该 `public/` 目录；
- 核查对应运行的 `audit/report.json` 与 SQLite `cells` 记录；
- 运行 `python -m cellcloak verify --run <run-id>` 重新核验；
- 用新的契约或阻断策略重新运行，不得覆盖旧台账证据；
- 按组织的数据事件流程通知相关责任人。
